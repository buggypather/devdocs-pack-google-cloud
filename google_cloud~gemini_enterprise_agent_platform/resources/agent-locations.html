Supported locations for agents in Agent Platform

This page lists the supported locations for Google agents and agent infrastructure features in Gemini Enterprise Agent Platform.

Supported locations for agent infrastructure features provide data-at-rest residency for your data (including agent source code, deployment packages, session history, memory bank entries, and metadata) in the selected location. When an agent invokes foundation models or generative AI services, ML processing support is governed by the location and endpoint configured for that model.

For more information about regions and zones, see Geography and regions.

The following agent infrastructure features are supported in the zones, regions, and multi-regions listed in the table:

  • Runtime
  • Sessions
  • Agent Platform Memory Bank
  • Sandboxes (Code Execution, shell execution, Agent Platform Computer Use, and custom container images)
  • Agent Gateway

Multi-regional and global endpoints

Memory Bank, Sessions, Runtime, and Code Execution support multi-regional endpoints. Memory Bank and Sessions also support global endpoints. For global requests, set your location to global. For multi-regional requests, set your location to us or eu.

Note: You can't use CMEK if your Memory Bank or Sessions is configured to use the global endpoint. Cloud Key Management Service requires encryption keys to reside within a fixed geographic data residency boundary. Because the global region lacks a physical geographic boundary, it is barred from encrypting localized regional or multi-regional resources.
Note: You can't use CMEK if your Runtime is configured to use a multi-regional endpoint.

  • Gemini Deep Research Agent (Preview)
