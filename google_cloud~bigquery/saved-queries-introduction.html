Introduction to saved queries

Saved queries let you create, manage, and share SQL scripts in BigQuery. Changes to a saved query are automatically saved so that you don't lose your work when you close the query editor. Saved query capabilities are available only in the Google Cloud console.

About saved queries

Saved queries improve collaboration and query management with the following options:

  • Share saved queries with specific users and groups by using Identity and Access Management (IAM).
  • Review the query version history.
  • Revert to or branch from previous versions of the query.

Saved queries are BigQuery Studio code assets powered by Dataform. Notebooks are also code assets. All code assets are stored in a default region. Updating the default region changes the region for all code assets created after that point.

Saved query security

You control access to saved queries by using Identity and Access Management (IAM) roles. For more information, see Share saved queries and Security considerations for saved queries.

Limitations

Saved queries have the following limitations:

  • You can grant public access to saved queries only to the allAuthenticatedUsers principal. You can't grant access to saved queries to the allUsers principal.
  • If your Google Cloud project contains more than 2,500 classic saved queries, you can't use batch migration to migrate classic saved queries to saved queries.

Classic saved queries (Deprecated)

Deprecated: Saved queries, available in BigQuery Studio, will fully replace classic saved queries in the future. The deprecation timeline is being reviewed. For more information, see Deprecation of classic saved queries. To learn how to migrate to saved queries, see Migrate classic saved queries.

To edit existing classic saved queries after they are fully deprecated, you must migrate them to BigQuery Studio.

Classic saved queries are an older method for saving and sharing SQL. Unlike BigQuery Studio saved queries, they only retain the query text and the SQL version (legacy SQL or GoogleSQL).

In the Google Cloud console, they appear in the (Classic) Queries folder within the Explorer pane. (If you haven't enabled BigQuery Studio, they appear in the Saved queries (NUMBER) folder in the Classic Explorer pane).

There are three types of classic saved queries:

  • Personal (person): visible only to the user who created them.

    • Note: If a personal query contains sensitive information, you must delete the query or remove the sensitive data prior to migration.

  • Project-level (people): visible to any principal with the required permissions.

  • Public (share): visible to anyone who has the link to the query.

IAM roles for migration and access

The following predefined BigQuery IAM roles include the required Dataform permissions to help you transition to BigQuery Studio saved queries:

  • BigQuery Admin (roles/bigquery.admin) includes roles/dataform.admin permissions.
  • BigQuery Job User (roles/bigquery.jobUser) and BigQuery User (roles/bigquery.user) include:
    • dataform.locations.get
    • dataform.locations.list
    • dataform.repositories.create
    • dataform.repositories.list

If you don't have one of these predefined roles, you request the required permissions. Custom roles aren't automatically updated and must be edited manually.
