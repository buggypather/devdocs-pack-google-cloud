Prevent users from granting access

Denying permissions that let users grant access helps you prevent unauthorized privilege escalation and tighten your security controls. This document describes how to identify these permissions and create a deny policy that blocks them for most users while allowing exceptions for trusted principals.

Required roles

To get the permission that you need to create a deny policy, ask your administrator to grant you the Deny Admin (roles/iam.denyAdmin) IAM role on your organization. For more information about granting roles, see Manage access to projects, folders, and organizations.

This predefined role contains the iam.denypolicies.create permission, which is required to create a deny policy.

You might also be able to get this permission with custom roles or other predefined roles.

Identify permissions that let users grant access

Before you create a deny policy to prevent users from granting access, determine which permissions you want to deny.

The following permissions let users grant access:

  • Permissions ending in setIamPolicy. The most broadly permissive of these permissions are those for Resource Manager resources because allow policies for those resources are inherited by all descendant resources. These permissions are as follows:

    • cloudresourcemanager.googleapis.com/projects.setIamPolicy
    • cloudresourcemanager.googleapis.com/folders.setIamPolicy
    • cloudresourcemanager.googleapis.com/organizations.setIamPolicy

    Other resources also have setIamPolicy permissions—for example, Compute Engine instances have the permission compute.googleapis.com/instances.setIamPolicy. To prevent users from modifying allow policies for these resources, add these permissions to your deny policy.

    For a full list of deniable permissions ending in setIamPolicy, go to Permissions supported in deny policies and search for setIamPolicy.

  • The iam.googleapis.com/roles.update permission, which lets users modify custom roles. Users with this permission can add permissions to custom roles, effectively granting themselves or others those permissions.

  • Permissions to modify Unified Access Policies (UAPs) and bind them to resources. These permissions are as follows:

    • The iam.googleapis.com/accesspolicies.update permission, which lets users update existing UAPs.
    • Permissions ending in createPolicyBinding. These permissions exist for every resource that you can bind UAPs to. For projects, folders, and organizations, these permissions are as follows:
      • cloudresourcemanager.googleapis.com/projects.createPolicyBinding
      • cloudresourcemanager.googleapis.com/folders.createPolicyBinding
      • cloudresourcemanager.googleapis.com/organizations.createPolicyBinding

    Alternatively, you can prevent all users from binding UAPs to resources by enforcing the iam.managed.disableAccessPolicyBinding organization policy constraint in your organization. However, this organization policy doesn't prevent users from modifying existing UAPs that are already bound to resources.

Deny access change permissions

After you determine which permissions you want to deny, create a deny policy for your organization that denies these permissions.

Console

  1. In the Google Cloud console, go to the Deny tab on the IAM page.

    Go to IAM

  2. Select your organization.

  3. Click add_box Create deny policy.

  4. In the Policy name section, define the policy ID by doing one of the following:

    • In the Display name field, enter a display name for the policy. Filling out this field automatically fills out the ID field. If you want to change the ID of the policy, update the text in the ID field.
    • In the ID field, enter an ID for the policy.

  5. In the Deny rules section, add a deny rule that blocks access change permissions:

    1. In the Denied principals field, add the principals to deny access to. To deny access change permissions to all users, use the value principalSet://goog/public:all. For a full list of values that you can use, see Principal identifiers for deny policies.

    2. In the Exception principals field, add the trusted principals that you want to let grant access. For a full list of values that you can use, see Principal identifiers for deny policies.

      Note: If a principal set in the list of denied principals includes service agents—for example, the principal set principalSet://goog/public:all—then we recommend adding your service agents as exceptions in the deny rule. This helps ensure that your services continue to function properly. When adding service agents as exceptions, use the project, folder, or organization's service agent principal set.

    3. In the Denied permissions section, add the permissions that you identified in Identify permissions that let users grant access.

    4. Optional: Add a denial condition that specifies which resources are affected by this rule. For example, you can add a condition to ensure that the policy applies only for resources with the prod tag value. For more information about denial conditions, see Conditions in deny policies.

  6. Click Create.

gcloud

The gcloud iam policies create command creates a deny policy for a resource.

Before using any of the command data below, make the following replacements:

  • POLICY_ID: An identifier for the deny policy.
  • ORG_ID: The numeric ID of the organization where you want to create the deny policy.

  • POLICY_FILE: A file that contains the deny policy that you want to set. Use the following format for the deny policy: 

    {
  "displayName": "POLICY_NAME",
  "rules": [
    {
      "denyRule": {
        "deniedPrincipals": [
          DENIED_PRINCIPALS
        ],
        "exceptionPrincipals": [
          EXCEPTION_PRINCIPALS
        ],
        "deniedPermissions": [
          ACCESS_CHANGE_PERMISSIONS
        ],
        DENIAL_CONDITION
      }
    }
  ]
}

    Replace the following values:

    • POLICY_NAME: The display name for the deny policy.
    • DENIED_PRINCIPALS: The principals to deny access to. To deny access change permissions to all users, use the value "principalSet://goog/public:all". For a full list of values that you can use, see Principal identifiers for deny policies.

    • EXCEPTION_PRINCIPALS: The trusted principals that you want to let grant access. For a full list of values that you can use, see Principal identifiers for deny policies.

      Note: If a principal set in the list of denied principals includes service agents—for example, the principal set principalSet://goog/public:all—then we recommend adding your service agents as exceptions in the deny rule. This helps ensure that your services continue to function properly. When adding service agents as exceptions, use the project, folder, or organization's service agent principal set.
    • ACCESS_CHANGE_PERMISSIONS: The permissions that you identified in Identify permissions that let users grant access.
    • DENIAL_CONDITION: Optional. A denial condition that specifies which resources are affected by this rule. For example, you can add a condition to ensure that the rule applies only for resources with the prod tag value. For more information about denial conditions, see Conditions in deny policies.

Execute the following command:

Linux, macOS, or Cloud Shell

gcloud iam policies create POLICY_ID \
    --attachment-point=cloudresourcemanager.googleapis.com/organizations/ORG_ID \
    --kind=denypolicies \
    --policy-file=POLICY_FILE

Windows (PowerShell)

gcloud iam policies create POLICY_ID `
    --attachment-point=cloudresourcemanager.googleapis.com/organizations/ORG_ID `
    --kind=denypolicies `
    --policy-file=POLICY_FILE

Windows (cmd.exe)

gcloud iam policies create POLICY_ID ^
    --attachment-point=cloudresourcemanager.googleapis.com/organizations/ORG_ID ^
    --kind=denypolicies ^
    --policy-file=POLICY_FILE

If successful, this command returns no output. To print a detailed response, use the --format=json flag.

REST

The policies.createPolicy method creates a deny policy for a resource.

Before using any of the request data, make the following replacements:

  • ORG_ID: The numeric ID of the organization where you want to create the deny policy.
  • POLICY_ID: An identifier for the deny policy.
  • POLICY_NAME: The display name for the deny policy.
  • DENIED_PRINCIPALS: The principals to deny access to. To deny access change permissions to all users, use the value "principalSet://goog/public:all". For a full list of values that you can use, see Principal identifiers for deny policies.

  • EXCEPTION_PRINCIPALS: The trusted principals that you want to let grant access. For a full list of values that you can use, see Principal identifiers for deny policies.

HTTP method and URL: 

POST https://iam.googleapis.com/v2/policies/cloudresourcemanager.googleapis.com%2Forganizations%2FORG_ID/denypolicies?policyId=POLICY_ID

Request JSON body: 

{
  "displayName": "POLICY_NAME",
  "rules": [

To send your request, expand one of these options:

curl (Linux, macOS, or Cloud Shell)

Note: The following command assumes that you have logged in to the gcloud CLI with your user account by running gcloud init or gcloud auth login , or by using Cloud Shell, which automatically logs you into the gcloud CLI . You can check the currently active account by running gcloud auth list.
